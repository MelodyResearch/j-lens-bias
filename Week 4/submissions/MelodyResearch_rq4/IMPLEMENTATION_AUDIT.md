# Pre-implementation audit, 2026-10-20

This audit reads existing work; it does not revise or rerun it. The shared Google Doc's main RQ4 section summarizes several interventions, including the warnings that a strong swap can move a model off distribution and that a group swap may invert rather than neutralize a preference. Its author paragraphs describe csinatra's generated-answer and control work, Radnitz's two-pass swaps, Syed's limited Age result, and Keshav's failed behavioral transfer. The proposed experiment retains these distinctions.

## Historical code and claim boundaries

* `Week 4/week4_multi_ablation.py:25–28,96–99` calls `tokenizer.encode(text)[0]` for target words and adds probabilities across token strings. The code does not assert one-token encoding, compare full phrase likelihoods, or deduplicate IDs before summing. Different spellings may map to the same first ID and would then be counted twice. These are unresolved validity risks for the reported P(she)/P(he), not proof that a specific ID is wrong; no historical results are altered.
* `Week 4/week4_multi_ablation.py:43–59` mutates hook output in place, and `:82–92` removes hooks after the forward call without `finally`. An exception can leave hooks attached. The script targets the final sequence position in a forward pass, but it does not measure generation or check the hook's invocation and displacement.
* `Week 4/week4_multi_ablation.py:37–41,62–74` uses one random direction orthogonalized to `she`, plus layers 22–30 of a 4B model. It cannot establish a distribution of null effects or specify valid layer sites for a 0.8B model.
* `Week 4/week4_ablation_results.json` contains 39 aggregate rows across three short pronoun prompts and intervention settings. It contains no generated text, per-item BBQ evidence score, or activation norm. `Week 4/week4_ablation_report.md` calls the he/she probability reversal a solution and asserts maintained fluency; those claims outrun the saved metrics. A reversal can be directional inversion without parity or evidence following.
* `Week 4/submissions/csinatra_week_4/scripts/interventions.py:120–166,259–280` implements clean-coefficient caching for two-pass swaps and removes generation hooks in `finally`. `:233–256` implements clean projection ablation. Its notebook's J-Lens token vector is `U[token] @ J_l` and it scores generated text as well as teacher-forced full answers. The comparison is largely on 4B and its selected prompts, so it is method guidance rather than a direct result for 0.8B Age format pairs. Its notebook also filters some comparisons to prompts with a classifiable baseline or a changed evidence answer; selection must be documented when interpreting conditional percentages.
* `Week 3/scripts/run_week3_experiment.py:594–626` establishes the last-token `Answer:` position, released lens layers, and rank-gap convention. Its saved rows are immutable inputs for the new work. A J-Lens direction built from all meaningful constituent IDs is related to, but not identical to, Week 3's minimum constituent rank score; the new experiment must report both definitions clearly.
